# Native feature API call-density research

Researched 2026-09-07. Public web only; zero authenticated Onshape/MCP calls. This note records documented behavior and proposals, not live modeling validation.

## Most actionable findings

1. **Batch update cannot create a tree.** `POST /partstudios/d/{did}/w/{wid}/e/{eid}/features/updates` requires existing features. It patches top-level parameters and optional suppression, rather than replacing complete features. Do not spend a call testing it as a bulk-add endpoint. The official generated Go client explicitly states this contract. [Official source, UpdateFeatures](https://raw.githubusercontent.com/onshape-public/go-client/master/onshape/api_part_studio.go)

2. **One sketch call can carry the entire sketch.** The native sketch payload has `entities` and `constraints` arrays. Bundle all coplanar profiles, holes, construction geometry, dimensions and constraints that logically belong together. Adding the sketch returns its `featureId`, so retain it for the next extrusion. Use a query string for default planes (`query=qCreatedBy(makeId("Front"), EntityType.FACE);`) to skip a plane lookup. An extrusion can reference the sketch through `BTMIndividualSketchRegionQuery-140`. These mechanisms are documented; arbitrary complicated constraints still need validated payload templates. [Official feature API guide](https://onshape-public.github.io/docs/api-adv/featureaccess/)

3. **Reuse a native template by copying its whole Part Studio, then batch-update its dimensions.** The supported endpoint is `POST /elements/copyelement/{targetDid}/workspace/{targetWid}`. Body source fields: `documentIdSource`, `workspaceIdSource`, `elementIdSource`; optional `anchorElementId` controls tab placement. Response is `BTDocumentElementInfo`. The opportunity is one copy call plus one batch update for a variant of an already-built tree; this is an inference combining two documented APIs, and requires verifying copied feature IDs and retained internal references before budgeting it as exactly two calls. No bulk array of source elements appears in the published copy schema. [Official endpoint code](https://raw.githubusercontent.com/onshape-public/go-client/master/onshape/api_element.go), [official request schema](https://raw.githubusercontent.com/onshape-public/go-client/master/onshape/model_bt_copy_element_params.go)

4. **Pack related parameters into a native Any variable map when individual Variable features would waste calls.** Onshape officially supports maps, arrays and functions in Any variables, with FeatureScript expressions in dimension fields. Proposed single variable `params = {"width": 100 * millimeter, "height": 20 * millimeter}` lets later expressions reference `#params.width` and `#params.height`. This retains ordinary native downstream sketches/features and requires only one variable feature. The tradeoff is a map expression editor instead of a separately listed variable per dimension. Exact REST payload and map access should be verified once using a known working template. [Official Variable documentation](https://cad.onshape.com/help/Content/PartStudio/variable.htm), [official parameter expression documentation](https://cad.onshape.com/FsDoc/uispec.html)

## Community discoveries and what primary evidence supports

- A February 2025 forum contribution supplies a Postman collection that builds sketches, extrudes, fillets and a mirror, and highlights feature-ID-based query strings as the useful trick. The official guide independently confirms query strings and consuming returned IDs, so the reusable lesson is to build queries from known feature provenance instead of fetching transient geometry IDs between every operation. The attachment is a lead, not executed evidence. [API for beginners discussion](https://forum.onshape.com/discussion/22988/api-for-beginners)
- A December 2024 copying failure was reproduced by Onshape staff; a community developer traced it to a very old source Part Studio library and reported a library update resolved it. This demonstrates template-copy inputs can be defective even when the request is correct. Do not blindly repeat copy calls or use the thread's delete/restore workaround in this project. Prefer a current, minimal, tested template. [Copy-element failure discussion](https://forum.onshape.com/discussion/26094/post-elements-copyelement-did-workspace-wid-return-bad-request)
- A December 2024 dimension API question reports successful coincident constraints but unresolved DISTANCE references. It is evidence that plausible JSON can return successfully while regeneration has errors. Sketch constraints should come from a known working native example, with actual feature status checked. [Dimension API discussion](https://forum.onshape.com/discussion/26109/adding-dimensions-to-sketch-features-via-api)
- Existing community MCP projects advertise per-sketch/per-feature tools, and CadScript advertises local planning and apply/verify tooling. These are useful implementation leads but no evidence of server-side multi-feature creation was found here. [hedless source README](https://github.com/hedless/onshape-mcp/blob/develop/README.md), [CadScript coverage matrix](https://github.com/ricokahler/onshape-cadscript/blob/main/COVERAGE.md)

## Boundaries and budget implications

- Native feature creation is documented as a single `feature` object per add call. `subFeatures` in serialized data is not evidence of a supported bulk insertion pathway; no verified example of using it that way was found.
- Custom FeatureScript can generate dense geometry, but its operations do not thereby become independent native feature-list entries. Official custom-feature documentation explicitly prevents modifying other features in the feature list. [Official custom-feature limits](https://cad.onshape.com/help/Content/PartStudio/add_custom_features.htm)
- The template strategy amortizes initial construction over repeated similar parts. It does little for six completely unrelated first-time geometries unless they share a useful feature topology.
- For a simple new part, a practical supported minimum is create Part Studio + complete sketch + extrusion = three mutations before verification/assembly. Reusing a supplied empty tab removes the first mutation. Sketch holes at the same extrusion depth can be represented in the original profile rather than separate cut features; validate region selection semantics for nested profiles.
- For this exploration, prioritize one robust native sketch/extrude family with editable constraints, then template reuse where actually similar. Preserve calls for checking regeneration and assembly placement. Parallelizing calls reduces latency, not API usage; public research and local payload generation cost no authenticated Onshape calls.

## Skill candidates

- Keep a vetted native payload library per feature/constraint type with its API/library version and successful regeneration evidence.
- Before every request, record what IDs, geometry, states and metadata it can return; consume those outputs rather than performing redundant GETs.
- Keep the call ledger at underlying authenticated HTTP request granularity, including failed calls.
- Separate confirmed public contracts, community reports, local inference and live validated behavior.
- Treat copied native feature trees as reusable compiled templates; derive variants with one bulk parameter update after checking ID semantics once.
